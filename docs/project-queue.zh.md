# 项目库与串行队列

默认进入任务工作台：任务队列、待提交、已完成、回收站四个视图。顶部运行状态独立刷新，切换视图和搜索不会改变全局计数。
在“待提交”中使用可增删行的表格，每行一个 YouTube 视频链接，分别选择「字幕版」「配音版」或「字幕+配音版」。
也可以多选上传本地视频，再为每个文件分别选择输出版本。
配音版只生成配音视频，不额外生成原声字幕视频；仍会保留工作流需要的字幕文件。
点击「加入选中的 N 个视频」或「加入全部 N 个视频」后，按各行选择串行处理，同一时刻只执行一个项目。
共享设置在提交时保存，修改侧栏设置不会改变已经排队的任务。
提交时按 YouTube 视频 ID 检测整个项目库中的重复视频，兼容 watch、短链接、shorts、embed 和 live 链接。
默认跳过已有视频并提示原项目；需要补生成某个版本时，在原项目中调整输出。
只有勾选「重新创建已有视频的项目（会重新处理）」才会创建独立的新项目。

## 存储

```text
Projects/
  queue.sqlite3
  drafts.json                    # 持久化待提交链接、标题和输出选择
  service.log
  logs/<项目 ID>.log
  2026-10-24_视频标题/
    project.json
    source_metadata.json          # YouTube 标题与视频 ID
    config.snapshot.yaml         # 提交时的配置，保留原始值
    config.runtime.yaml          # 项目运行配置，例如识别出的源语言
    custom_terms.xlsx            # 提交时的术语表
    remaining_plan.json          # 失败/中断时剩余阶段
    output/
      <源视频>
      workflow_state.json
      output_sub.mp4
      output_dub.mp4
      log/
      audio/
      gpt_log/
      versions/
```

项目目录在提交时创建。YouTube 项目取得标题前使用 pending 名称，取得标题后改为创建日期加标题。
页面会在后台通过 YouTube oEmbed 提前获取排队项目的显示标题，不必等到下载阶段。
oEmbed 返回 401 或其他错误时，自动改用 yt-dlp 只读取元数据；排队项目使用其配置快照中的 YouTube 设置，输入预览使用当前设置。此过程不下载视频。
标题查询失败会限频重试，不影响处理队列；项目目录仍由正式工作进程在启动时安全重命名。
非法字符会替换，过长标题会截短，重名加序号。项目 ID 不随目录名变化。
项目完成后留在原处，不再要求搬到 history。
Projects 已加入 Git 忽略规则。

「导入旧 output 项目」复制现有工作目录，保留源视频、审核确认、成果和历史版本，不删除原目录。
导入时需要额外的磁盘空间；请先等旧任务结束再导入。旧 history 不会自动搬动。

## 状态和控制

- 失败：保存失败阶段和原因，继续下一个视频；项目详情中可以重试。
- 超时：默认每阶段 120 分钟，提交时可以调整。终止该项目的进程树后继续队列。
- 等待审核：保留审核文件，先处理其他项目。保存文件后点击「确认审核并继续」。
- 停止当前项目：终止当前项目及其子进程，继续下一个。
- 暂停队列：当前项目继续完成，暂不启动下一个。点击恢复后继续。
- 移除排队项目：取消执行，保留项目文件。
- 清理停止/失败记录：勾选任务行，在“更多操作”点击「移到回收站」，即可从当前列表隐藏，文件和任务记录仍保留。在“回收站”可选择“恢复并排队”或“仅恢复记录”。
- 表格操作：勾选任务行后，可直接点击表格下方的「更多操作 → 移除排队任务」或「归档」，支持多选。
- 归档：仅限已完成项目，将完整目录移至安装目录下的 `archive/history/`，保留成果、审核状态、版本和运行日志。归档项目从默认列表隐藏。
- Windows 拒绝直接移动目录时，改为复制并逐文件校验大小和 SHA-256，校验通过后才登记归档并从当前列表隐藏。被占用或无法移动的原目录额外保留，不强制删除；界面会明确提示保留路径。
- 归档错误会持续显示，不会被自动刷新清掉；复制或校验失败时，原项目保持原状态。
- 查看/恢复归档：进入「已完成 → 已归档」，选中后点击「恢复到项目库」，即可移回 Projects；恢复不会自动重新处理。
- 重试：输入、配置和翻译版本未变时，从保存的失败阶段继续；变动时重新计算工作流。
- 更新输出：可以追加配音、修改字幕模式；已有成果按原工作流保存到 versions。

队列执行器是独立后台进程，关闭或刷新浏览器不会停止处理。
机器/执行器意外中断后，重新打开 VL 会恢复队列服务，未启动的任务继续执行，
原来运行的项目显示「意外中断」，点击恢复后复用有效成果。
后台进程由操作系统锁保护，多个页面不会启动多份执行器。
Windows 使用 Job Object 管理工作进程及其子进程；Linux/macOS 使用独立进程组。

## 实现边界

本阶段严格串行，尚未加入 GPU 与远程 API 的阶段交错调度。
工作进程通过 VL_OUTPUT_DIR、VL_CONFIG_PATH、VL_TERMS_PATH 绑定项目路径，
启动后不切换工作目录。模型目录和应用资源继续相对于 VL 安装目录解析。
交互工作流和队列共用 core/utils/pipeline.py 与原有 Project 规划、审核和版本机制。
SQLite 保存队列；每个项目保存自己的工作流和剩余阶段，页面不承担任务执行。

表格中的处理时间不含排队和人工审核等待，重试累计计时。旧项目按最近一次后台进程的起止时间补算。
预计剩余按相同配置的已完成项目，分阶段取耗时与视频长度的比例中位数，再按当前视频长度折算。
数据不足时显示「暂无法估算」，超过估算时显示仍在处理；估算不包含排队等待。

## 验证

当前列表选中已停止、失败或中断的任务，可直接点击表格下的“重新排队”，无需滚动到项目详情。重新排队会清除选择冻结并刷新状态；若原项目目录已缺失，则提供“重新创建并排队（使用当前设置）”，保留原输出版本选择，以当前共享配置建立新项目，并隐藏旧的缺失记录。

归档移动失败的诊断日志位于 `Projects/logs/archive.jsonl`：记录源/目标路径、错误码、目录与子项访问探测、Restart Manager 可识别的文件占用进程，以及复制/校验分别的耗时。探测不修改权限、不关闭进程；未发现占用不代表排除了目录句柄或安全软件限制。`scripts/diagnose_archive.py <项目目录>` 可做只读检查。SQLite 使用 `Projects/queue.sqlite3`，写事务短暂生成的 `queue.sqlite3-journal` 是正常事务日志，不要手动删除。

“从队列移除所选排队项”会同时取消任务并隐藏记录，保留项目文件。可在“回收站”中恢复；“仅恢复记录”保持已停止状态，“恢复并排队”会继续处理。

勾选一个排队中的视频，可用“上移 / 下移 / 移到队首 / 移到队尾”改变执行顺序。顺序保存在数据库，重启后保留；正在运行的视频不会被移动或中断。新加入的视频默认放在已排序的排队项之后。已运行的旧后台服务需要重启才能加载排序功能，界面会提示；请先等待当前视频完成并暂停队列。

批量输入表的“标题”列只读。输入或修改 YouTube 链接后，按 Enter 或离开单元格即获取标题，无需提交队列；多链接最多同时获取四个，结果缓存一分钟。获取失败会在该行提示，仍可提交处理。标题获取不下载视频。
输入表可勾选“本次加入”：勾选后仅提交勾选行；没有勾选时提交全部非空链接。提交成功只清除本次提交的行，未选链接、标题和输出选择保留在当前页面，方便下次提交。已获取的标题会直接用于队列记录和项目目录，不再先显示 pending 临时名。提交校验失败时保留输入。

使用运行 VL 的 Python 环境，在仓库根目录执行：

```powershell
python -m unittest scripts.test_project_queue scripts.test_project_worker scripts.test_project_ui
python -m unittest scripts.test_workflow_plan scripts.test_workflow_ui scripts.test_workflow_video_outputs
```

队列测试使用独立临时项目和可控工作进程，覆盖失败/超时后继续、取消、重启、互斥、配置隔离及旧项目导入。
工作进程集成测试使用合成视频和预置上游成果，实际调用 FFmpeg 验证审核后继续、两种输出和历史版本。
这些测试不调用付费翻译或 TTS API，也不下载真实 YouTube 视频。

## 工作台交互

### 发音词典

点击页面顶部“发音词典”，编辑“词语 / 配音读法”并保存。VL 根目录的 `glossary.yaml` 使用兼容 IndexTTS 的映射格式：

```yaml
弹容量:
  zh: dan4容量
```

词典在发送 IndexTTS 请求前应用，不修改字幕或翻译文件，无需重启模型。使用带声调数字的拼音（`dan4` 表示 dàn），推荐按完整词语指定，避免影响“弹簧”等其他读法。长词优先、单次替换，不会反复处理替换结果。

每个新生成的音频保存 `.pronunciation.json`，记录原始文本与实际发送文本。规则增加、修改、删除后，只让实际读法发生变化的缓存失效；未匹配规则的旧缓存可继续使用。被替换的旧音频保存在音频临时目录的 `pronunciation_versions/`，不会直接丢弃。

已有成片不会自动修改。在未归档项目详情中点击“按当前词典更新配音”，可重新排队执行配音、混音和成片合成，复用字幕、参考音频与未受影响的语音。旧混音和视频按项目版本机制保留；归档项目须先恢复。词典是全局规则，保存后用于后续的 IndexTTS 请求。

项目详情包含“原始标题”和“中文标题”。点击“翻译成中文”使用当前 LLM 翻译阶段配置生成简体中文标题，结果保存在项目记录中，刷新不会再次调用。可点击“重新翻译中文标题”更新；失败会保留已有译文。中文标题不改变项目目录、队列顺序或视频处理状态，归档和恢复后仍保留。

Windows 归档若报 WinError 5，除 Restart Manager 外还会只读检查常见应用持有的文件及目录句柄，写入 `archive.jsonl` 的 `open_handles`。已定位占用时跳过较慢的全树探测。资源管理器打开项目内部的 `output` 子目录就可能阻止移动整个项目，即使 DELETE 访问探测成功且 Restart Manager 无占用记录；关闭或离开这些子目录后再归档即可。`scripts/inspect_archive_handles.py <项目目录>` 可手动定位，不会关闭原句柄或终止进程。

顶部运行状态与计时每 2 秒更新；任务列表每 5 秒检查变化。正在运行任务的实时耗时和剩余估计仅在顶部展示，避免秒数变化导致可选表格控件重新创建。表格样式使用固定 UUID；任务队列不再显示“处理时间”和“预计剩余”两列；已完成列表保留“总处理时间”。日志不再写入每次读取的时钟时间，内容未变时保持显示稳定。

无选中任务时不显示批量操作按钮。选中后只显示适用的主要操作，排序、移除、仅恢复记录放在“更多操作”中。项目详情与成果按需展开，日志默认折叠且固定 300px 高度。任务队列只展示项目、输出、状态、阶段和问题；已完成列表显示总处理时间；来源 URL、加入时间、项目路径保留在详情中。成功提示为短暂通知，失败与归档警告可手动关闭。

待提交清单原子写入 Projects/drafts.json，输入提交后仅清除成功加入的行；去重跳过的链接保留，并提供前往原记录所在视图的入口。磁盘草稿为本机共享清单，多个页面同时编辑时最后保存的版本生效。
