# 翻译阶段质量改进与校对评估

## 翻译流程

- 先按原文句末标点识别连续句段，再按 `translation_chunk_chars` / `translation_chunk_lines` 合批。这两项是软目标，不再为了满足行数而切断正常句子。
- `translation_context_lines: 4`：每批前后至少 4 行只读原文参考，边缘不足时取现有行，并扩展到句段边界。上下文可能跨越不止一个相邻批次。
- `translation_max_sentence_lines: 28`：缺少标点的长段按此上限分段；单独一条超长字幕不会被程序拆开。标点只能近似句界，不是真正的语义解析。
- 翻译和可选润色都要求按完整句意理解词义、条件和指代；允许同一句段相邻行调整语序，但每条信息只能出现一次。字幕换行不等于句子结束。上下文不能被重复翻进正文。
- 批次失败时只在句段边界拆小，并把兄弟子批补进前后文。单句重试耗尽会报错，不继续拆成孤立片段。
- 可选困难句二次翻译扩展到完整句段，参考相邻原文和原译文；风险比例只约束种子行，实际处理行数可能增加。
- 并发结果按批次 ID 回填，避免重复/相似原文被匹配到另一个批次。
- `Translation Workflow=sentence_context_v1` 标记新流程。`Translation Before Timing Trim` 保留最终按时长压缩前的译文，便于区分翻译与后续压缩造成的问题。

没有自动打开润色或关闭校对。每批仍是一轮翻译调用（开启润色/困难句时另计），上下文和提示词增加会增加 token 用量。重试也会额外计费。

已存在的翻译表仍遵守原来的跳过逻辑：点击“重新运行 LLM 校对”只重做校对，不会重新翻译。新视频正常运行即使用新翻译流程；旧视频应先归档/备份，再通过现有重新翻译流程运行。不会自动覆盖现有结果或清除缓存。

## 人工评估校对是否值得保留

新校对表增加两列 **Human Verdict**、**Human Note**。它们由人填写，模型不能代填。
建议先保留 `suggest` 模式，在应用修改前评价：按完整句段阅读原文、校对前后译文，必要时听原音。

Human Verdict 可填：

| 值 | 含义 |
| --- | --- |
| fixed | 译文有修改，确实修复错误，未发现新错 |
| regression | 译文有修改，引入新错 |
| mixed | 同一行既修复错误又引入新错 |
| style_only | 只是换词/润色，没有实质纠错 |
| no_issue | 未修改，人工也没有发现问题 |
| missed | 已送审但未修改，人工发现漏检错误 |
| uncertain | 无法判断，需更多证据 |

空白=尚未人工评价，不表示成功。无需逐行强行评价；至少覆盖所有修改行，再抽查未修改的完整句段。跨行问题可在 Human Note 写明相关字幕行号；统计单位是行，不是独立错误数，不能把多行修复当作多个独立错误。

用项目 Python 环境执行只读统计（不会调用 LLM、写入或导出工作簿）：

```powershell
python scripts/analyze_proofread_quality.py output history
```

也可只传指定视频目录或 `.xlsx` 路径。输出 JSON 按视频及总体分别列出：送审、实际文本变化、人工评价、未评价、无效标签等计数。模型自报状态与人工结论分开列示，旧表缺少状态时标记 unknown。相同文件路径去重；不要同时传入同一视频的多个复制版本来计算总体。

至少选几个类型相近的视频比较，并在 Human Note 记录抽样方式。比较 `fixed`、`regression`、`mixed`、`style_only` 和未评价数，不用“改了多少行”代替收益，也不根据少量样本声称全片准确率。需要判断整个译文的质量，还应评估未修改行的 `missed`。

**重新校对会生成新候选，清空这两个人工评价列。先归档已评价工作簿。**
模型判定列描述的是校对意见；自动应用后的时长压缩还可能改变文本，评估时建议使用尚未自动应用的建议稿。
